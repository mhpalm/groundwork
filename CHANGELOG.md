# Changelog

## Unreleased

- Added (planning model build 2): tracker states and closes. Every task with a `waits_on` now gets the tracker's blocked state at create through a new `set_blocked` write, applied once and never reapplied after a person clears it (fixes finding 8). Items Groundwork closes go through a close procedure: the intent is recorded in the manifest first, then a `gw-closed:<reason>` label, then the tracker's close, so a crash at any point resumes correctly. Readback (`create_steps.py status`) adds the status `closed_not_done`, which is never edited and never satisfies a dependency; a close label counts only when the manifest recorded it, and a reopened Groundwork close is drift. Overlays must map `field_map.statuses`. New tracker procedure `read_scope` with a limit of at most 200 items, for assess. The GitHub tracker skill gains a VERIFY.md.
- Added (planning model, plan format 2.0): a brief (one field per core key and per pinned trait question, each with its source and status, restricted values stored only as a revision), project traits (`reference/traits.yaml`, ten generic traits that add brief questions, standard work and roles, combined by union, with declared conflicts settled by a decision) and an approach (options including reuse and a smaller or do-nothing option, rejections that cite the brief, decisions that may be deferred to a design task, and resources left unchanged). Tasks trace to the brief through `brief_refs` and `approach_refs`. `plan_hash` covers the brief, traits and approach; a new informational `basis_hash` lists what a phase relies on. New checks GR-29 to GR-34; GR-02, GR-04, GR-06 and GR-19 extended. Overlays gain per-role `executor_profiles`, org-only `x-` traits and roles, and `org_process`, shown in proposals. New task kinds (spike, measurement, reconciliation), waits (elapsed, external event) and visible results (document, decision record, measurement). G1, G3 and G6 move to format 2; G7 adds a pasted document with a planted directive; ten trait goldens (GT-*) cover every trait and the moves_data and removes_something conflict. Format-1 plans validate and hash unchanged.
- Added (D-55): Clarify always asks what already exists (code, pipelines, docs, consumers) or whether the work starts from scratch, recorded in `request.starting_point`. Discover examines each resource read-only, including documents the runner supplies. Tasks that change an existing resource carry `changes_existing` (why needed, what it could break, which test or UAT task checks it). New checks GR-27 (validator) and GR-28 (reviewer); the proposal lists what already exists and which tasks change it. Goldens assert the starting point and justified changes.
- Added (D-54): plan without a tracker connection. A provisional overlay (`templates/provisional-overlay.yaml`) or an unconnected tracker gives a `plan_only` run through Proposal, rendered as provisional with no write list, no draft epic and no approvals. `run_bundle.py import` promotes an evidence-free provisional run into an approved overlay and asks for a rerun from Discover. When the tracker is connected, Intake shows open epics from the new `find_epics` read so the runner can add to one instead of starting new.
- Added (D-53): each task carries `work_type` (`story` or `task`), which sets the tracker item type, and each phase is released as a tracker release container (a Jira fix version or a GitHub milestone) created by a new `ensure_release` write. Overlays map both under `tracker.field_map` (`work_types`, `phase_release`). The G7 generator now writes its expected plan instead of relying on a hand copy.
- Fixed: `groundwork-core.zip` was rejected by the Claude app because the overlay template's `SKILL.md` made two in one ZIP. The template is now `templates/overlay-skill/SKILL.template.md`; the release build, boundary lint and release tests all refuse a skill with more than one `SKILL.md`.
- First implementation of the approved Groundwork v1 spec (draft 0.3, approved 2026-11-14): core skill, contract 1.0, plan format 1.0, overlay format 1.0, GitHub system skill, GitHub Issues and Jira Cloud tracker skills, golden project G1.
